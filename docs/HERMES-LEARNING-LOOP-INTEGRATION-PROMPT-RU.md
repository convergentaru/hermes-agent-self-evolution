# Промпт для локального Hermes: проверить и подключить Verified Learning Loop

Репозиторий проекта:
https://github.com/convergentaru/hermes-agent-self-evolution/tree/feat/local-verified-learning-loop

Документация:
https://github.com/convergentaru/hermes-agent-self-evolution/blob/feat/local-verified-learning-loop/docs/LOCAL-VERIFIED-LEARNING-LOOP-RU.md

## Задача

Не пересказывай документацию и не ограничивайся планом. Проверь код и тесты в репозитории, затем безопасно подготовь интеграцию с **моей текущей локальной установкой Hermes**, сохранив её baseline.

### 1. Сначала проверить реализацию

- Найди текущую рабочую копию репозитория и посмотри git status, чтобы не потереть изменения.
- Прочитай `evolution/learning/loop.py`, тесты `tests/core/test_learning_loop.py` и документацию.
- Запусти относящиеся к learning-loop unit tests в временной среде; не запускай optimizer, который вызывает внешние LLM API.
- Проверь поддерживаемую версией Hermes CLI интеграцию, профильные каталоги и способы вызова инструментов. Не угадывай CLI-флаги, схему session DB или пути.

### 2. Найти самый маленький полезный способ подключения

Изучить актуальную документацию/код установленной версии Hermes для:
- точек подключения навыка;
- локальной истории сессии и доступных execution/tool logs;
- способа передать ограниченный контекст из одобренных playbooks перед задачей;
- способа сохранить краткий результат и evidence после задачи.

Если формат session DB не подтверждён, не читать сырые базы наугад и не импортировать историю автоматически. Начни с явного локального вызова learning-loop из отдельного навыка/скрипта.

### 3. Использовать двухфазный протокол

**Фаза A: наблюдение (не меняет активное поведение).**
- После реальной задачи предложи/запиши краткое событие без полного транскрипта и без секретов.
- Создай кандидат правила только если есть конкретная коррекция/ошибка или подтверждённый успешный повторяемый способ.
- Кандидаты остаются предложениями и не попадают в активный контекст автоматически.

**Фаза B: проверка перед активацией.**
- Для одного узкого навыка подбери минимум 5 повторяемых тестовых кейсов.
- Сними baseline и candidate на неизменной модели, версии Hermes, инструментах и runtime.
- Сделай минимум 3 повтора на кейс.
- Сохраняй фактические outputs, логи, exit codes, model/environment IDs и hash тестируемого artifact вне публичного Git. Если тест опасен — использовать только безопасный synthetic fixture.
- Выполни `gate`; проверь, что он отклоняет отсутствие improvement и safety regression.
- Только после моей явной команды/одобрения выполняй `accept`. Не изменяй рабочие SOUL.md/SKILL.md автоматически.

### 4. Не сломать работающий Hermes

- Не менять голосовой ввод/вывод, STT/TTS, текущую рабочую модель/endpoint, лимиты контекста или глобальную конфигурацию.
- Не устанавливать новые пакеты без доказанной необходимости.
- Не запускать модели параллельно.
- Не копировать локальные сессии, пользовательские данные, MEMORY.md, USER.md, tokens или secrets в публичный Git.
- Не использовать `--yolo` как доказательство безопасного исполнения; не выполнять destructive action.
- Не трогать USB или внутренние диски.
- Все изменяемые локальные файлы предварительно копировать и сохранять в отдельной ветке; показать diff и команду отката.

### 5. Реальный критерий завершения

Интеграция не считается готовой из-за установки пакета или записи урока. Нужен один задокументированный реальный тест, где:
1. baseline выполняет задачу и фиксируются реальные метрики;
2. корректировка/lesson создаёт candidate;
3. candidate проверяется на тех же тестах;
4. gate выдаёт объяснимое решение;
5. кандидат остаётся неактивным без одобрения;
6. после явного одобрения retrieval возвращает только его и только в пределах установленного лимита контекста.

В конце отчитайся коротко: что реально выполнено; тесты и exit codes; какие локальные файлы изменены; что не тронуто; где находятся логи; какой один следующий шаг. Если чего-то не хватает, выполни всё доступное и назови точный блокер. Не говори «самообучение работает», если повторный тест не подтвердил улучшения.
